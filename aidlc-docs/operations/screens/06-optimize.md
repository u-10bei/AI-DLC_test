# 画面別説明書 — 最適化画面

**要件**: US-16（実行）/ US-17（重み調整）/ US-18（人員不足の診断）/ US-20（制限時間・最適性ギャップ）/ US-24（再最適化モード）
**利用者**: P-01（割当担当者）
**左ナビ**: 「最適化」
**前提**: イベントが選択されていること

---

## 画面の入力項目

| 項目 | 種類 | 既定 | 説明 |
|------|------|------|------|
| 再最適化モード | 選択 | 全体（FULL） | **全体（FULL）**=ゼロから計算 / **増分（INCREMENTAL）**=前回割当を踏まえて再計算（US-24） |
| 移動時間の重み | 数値 | 1.0 | 移動時間をどれだけ重視するか（0 以上） |
| 移動費用の重み | 数値 | 1.0 | 移動費用をどれだけ重視するか（0 以上） |
| 不公平の重み | 数値 | 0.5 | 負担の偏りをどれだけ抑えるか（0 以上） |
| 制限時間（秒） | 数値 | 300 | 計算の打ち切り時間（1 以上の整数） |
| 部署上限 | 数値 | 100 | 1 部署からの最大割当数（1 以上の整数） |
| 実行 | ボタン | — | 最適化ジョブを開始 |

> **重みのルール**: 3 つの重みは 0 以上で、**少なくとも 1 つは 0 より大きく**してください（すべて 0 は不可）。制限時間・部署上限は 1 以上の整数。

---

## 操作手順

1. 対象イベントを選び、最適化画面を開きます。
2. モード・重み・制限時間・部署上限を入力します（既定のままでも実行可）。
3. **[実行]** を押します。計算はジョブとして開始され、**約 2 秒ごとに状態が自動更新**されます。
   - 計算中は **[実行]** が押せなくなります（二重実行防止）。計算中に画面を離れても構いません。
4. 状態が終了（完了／実行不能／失敗）になったら結果を確認します。

---

## ジョブの状態表示

| 状態 | 表示 | 意味・対処 |
|------|------|-----------|
| 待機中 | 待機中 | 実行待ち |
| 計算中 | 計算中 | 求解中（最大で制限時間まで） |
| **完了** | 完了 | **割当件数・目的関数値・最適性ギャップ**を表示 → 割当結果画面へ |
| **実行不能（人員不足）** | 実行不能（人員不足） | 不足の内容を表示（US-18）。充足状況に戻り追加申告を取り付ける |
| 失敗 | 失敗 | 汎用エラー。時間をおいて再実行、または管理者に連絡 |

- **完了**時の「最適性ギャップ」は、得られた解が理論上の最適にどれだけ近いかの指標です（US-20）。制限時間内に打ち切った場合はその時点の最良解が返ります。

---

## エラーと対処

| 状況 | 表示 | 対処 |
|------|------|------|
| イベント未選択 | 「先にイベントを選択してください」 | イベント画面へ |
| 重みが全て 0 | 「少なくとも1つの重みは0より大きくしてください」 | いずれかの重みを正の値に |
| 重みが負 | 「重みは0以上で入力してください」 | 0 以上に |
| 制限時間／部署上限が 1 未満 | 「1以上の整数で入力してください」 | 修正 |
| 実行不能 | 状態「実行不能（人員不足）」+ 診断 | 充足状況で不足を解消 |

---

## 補足（要件の背景）

- 計算は避難所（施設）の必要人数・資格要件・従事可否・部署継続性・重複禁止といった制約を守りつつ、**居住地を考慮して移動負担を最小化**します。
- 資格要件が満たせない場合、システムは段階的に条件を緩めて解を探します（US-19、内部処理）。
- 求解は API とは別プロセスで走るため、計算中も他の画面の閲覧は妨げられません。
