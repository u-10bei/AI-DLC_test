## 1. 割り当ての原則

- **主担当ユニット**: そのストーリーの中核となるビジネスロジックを実装するユニット。1 ストーリーにつき 1 つ
- **協力ユニット**: 主担当を支援するユニット（永続化、API 公開、UI 描画など）

**U-07 api-orchestration** はすべてのストーリーの API 公開を、**U-08 frontend** はすべてのストーリーの UI 描画を担う。冗長を避けるため、下表では両者を特記が必要な場合のみ協力ユニットとして記載する。

上記 13 件に加え、ストーリーの受入基準で特定された不変条件も、担当ユニットへ引き渡す。

| 不変条件 | ユニット | 出典 |

| 移動費用は移動距離に対して単調非減少 | U-02 | US-15 |

## 5. 誤用・悪用シナリオのユニット割り当て（SECURITY-11、申し送り H-7）

| シナリオ | 統制を実装するユニット | 統制 |
|---------|---------------------|------|
| **MU-01** IDOR による他人の割当情報の閲覧 | **U-06 security** | `SEC-02 AuthorizationModule.authorizeResourceAccess()`（オブジェクトレベル認可） |
| **MU-02** CSV の数式インジェクション | **U-06 security**（`SEC-05`）＋ **U-03 data-management**（`A-04 CsvAdapter` が利用） | エクスポート時に `=`, `+`, `-`, `@` で始まる値をエスケープする |
| **MU-03** 総当たりによるログイン突破 | **U-06 security** | `SEC-03`（IP 許可リスト）、`SEC-04`（レート制限）、`SEC-01.recordFailedAttempt()`（アカウントロック） |
| **MU-04** 監査ログの隠蔽 | **U-06 security** | `P-04 AuditLogPort` に削除・更新メソッドを定義しない。追記専用ストレージ |

**MU-02 のみが 2 ユニットにまたがる**。`SEC-05 InputValidationModule.sanitizeCsvCell()`（U-06）を、`A-04 CsvAdapter.serialize()`（U-03）が呼び出す。U-03 → U-06 の依存が必要になるが、依存マトリクスでは U-03 は U-06 に依存していない。

**解決**: `sanitizeCsvCell()` は純粋関数であるため、**U-01 shared-kernel** ではなく **U-06 security** に置いたまま、U-03 が U-06 に依存する形にすると循環はしない（U-06 は U-01 にしか依存しないため）。ただし依存マトリクスの更新が必要である。

**代替案（採用）**: `A-04 CsvAdapter` の `serialize()` は、サニタイズ関数を**引数として受け取る**（依存性注入）。呼び出し元である `U-07 api-orchestration` が `SEC-05` の関数を注入する。これにより U-03 は U-06 に依存せず、依存マトリクスは変更不要である。

**この判断を Functional Design（U-03、U-06）へ申し送る。**
