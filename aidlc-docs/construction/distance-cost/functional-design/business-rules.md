# ビジネスルール — U-02 `distance-cost`

**作成日**: 2026-07-09
**ステージ**: CONSTRUCTION - Functional Design（ユニット 2 / 8）

---

## 1. 生成時バリデーション（fail closed / SECURITY-15）

U-01 と同じ規律に従う。**不変条件を満たさない値は、生成そのものを拒否する。**

---

### BR-D01: `CostBand` の生成

| 条件 | 判定 |
|------|------|
| `upper_bound_km` が正、または `None` | 生成する |
| `upper_bound_km <= 0` | **拒否**（`InvalidCostModelError`） |
| `amount_yen >= 0` | 生成する |
| `amount_yen < 0` | **拒否** |
| `upper_bound_km` が NaN または無限大 | **拒否** |

---

### BR-D02: `CostModel` の帯構造

| 条件 | 判定 |
|------|------|
| `bands` が 1 つ以上ある | 生成する |
| `bands` が空 | **拒否**（費用を算出できない） |
| `upper_bound_km` が**厳密に単調増加**している（`None` を除く） | 生成する |
| 単調増加でない | **拒否** |
| **`upper_bound_km = None` の帯がちょうど 1 つで、それが最後の帯である** | 生成する |
| `None` の帯が 0 個 | **拒否**（十分に大きな距離が、どの帯にも属さない） |
| `None` の帯が 2 個以上、または最後でない | **拒否**（到達不能な帯が生じる） |

**「`None` の帯が 0 個」を拒否する理由**: 全帯に上限があると、上限を超える距離に対して費用を算出できない。実行時に「どの帯にも属さない」という状態を生む。**生成時に拒否することで、実行時のこの状態が構造的に存在しなくなる。**

---

### BR-D03: `TravelParameters` の生成（U-01 の BR-04 を改訂）

| 条件 | 判定 |
|------|------|
| `detour_factor >= 1.0` | 生成する。1.0 未満は物理的に不合理（直線距離より短い経路は存在しない） |
| `average_speed_kmh > 0` | 生成する |
| `same_district_fixed_seconds >= 0` | 生成する |
| `cost_model` が妥当な `CostModel` である | 生成する（`CostModel` 自身が検証済み） |

**削除**: `unit_price_per_km` の検証（フィールド自体が削除される）。

---

### BR-D04: `CostModel` の費用関数が単調非減少であること（**最重要**）

**距離帯モデルは、設定次第で「遠くへ行くほど安くなる」費用関数を作れてしまう。**

#### 検証すべき条件

任意の距離 `d1 <= d2` に対し、`travel_cost_yen(d1, model) <= travel_cost_yen(d2, model)` が成立すること。

#### 検証方法（有限回で判定できる）

費用関数は帯ごとに単調非減少（`FLAT` は定数、`PER_KM` は非負係数の線形関数）である。したがって**帯の内部では単調性が保証されている**。

破れうるのは**帯の境界**だけである。各境界 `b_k`（帯 `k` の上限）について、次を検証すればよい。

```text
  帯 k の上限直前の費用   <=   帯 k+1 の下限直後の費用

  cost_at_upper_limit(band_k, b_k)  <=  cost_at_lower_limit(band_{k+1}, b_k)
```

| 帯 `k` の `rule` | 上限直前の費用（`d → b_k` の極限） |
|-----------------|--------------------------------|
| `FLAT` | `amount_yen` |
| `PER_KM` | `b_k * amount_yen` |

| 帯 `k+1` の `rule` | 下限直後の費用（`d = b_k` のとき） |
|-------------------|--------------------------------|
| `FLAT` | `amount_yen` |
| `PER_KM` | `b_k * amount_yen` |

**すべての境界でこの不等式が成立するとき、費用関数は全域で単調非減少である。**

#### 違反時

`InvalidCostModelError` を送出し、**`CostModel` の生成を拒否する**（fail closed）。

#### 既定値での検証

```text
帯 1: < 2 km,  FLAT 0 円
帯 2: < 10 km, FLAT 300 円
帯 3: ∞,       PER_KM 400 円/km

境界 2.0 km:  帯 1 の上限直前 = 0 円   <=  帯 2 の下限直後 = 300 円   ✅
境界 10.0 km: 帯 2 の上限直前 = 300 円 <=  帯 3 の下限直後 = 10.0 * 400 = 4,000 円  ✅
```

#### 違反する設定の例

```text
帯 2: < 10 km, FLAT 300 円
帯 3: ∞,       PER_KM 20 円/km

境界 10.0 km: 帯 2 の上限直前 = 300 円  <=  帯 3 の下限直後 = 10.0 * 20 = 200 円   ❌
```

**この設定は拒否される。** 許すと、最適化は 9.9 km の施設より 10.0 km の施設を「安い」と判定し、**より遠い施設へ職員を送ることを選ぶ**。

## 2. 計算ルール

### BR-D05: 地球半径（Q4=A）

```text
EARTH_RADIUS_KM = 6371.0088
```

IUGG 平均半径。**定数として明示する。担当者は変更できない**（Q4 で C を却下した）。

値の選択で結果が数十メートル変わる。プロパティテストの再現性のために固定する。

---

### BR-D06: 移動時間の丸め（Q5=A）

```text
travel_time_seconds(distance_km, average_speed_kmh) = ceil(distance_km / average_speed_kmh * 3600)
```

**切り上げ（`ceil`）**。移動時間を過小評価しない。

**根拠**: 災害時の参集計画において、移動時間の過小評価は職員の遅参を招く。過大評価のほうが安全側である。

**INV-09 への影響**: `ceil` により、迂回係数のごくわずかな増加が丸め後の値を変えないことがある。**INV-09 は「単調非減少」であり、厳密な単調増加ではない**（Q7=A、申し送り U01-H3）。

---

### BR-D07: 同一小学校区（Q2=A、FR-03.7）

職員の居住小学校区 ID と施設の所在小学校区 ID が**等しい**場合:

| 値 | 結果 |
|----|------|
| `distance_km` | **0.0** |
| `time_seconds` | **`params.same_district_fixed_seconds`**（既定 900 秒 = 15 分） |
| `cost_yen` | **0.0** |

**Haversine 距離を計算しない。** 代表点が同一なので結果は 0 だが、明示的に分岐することで意図を示す。

**移動時間のみ固定値とする理由**（FR-03.4）: 距離 0 として扱うと、同一校区内の移動負担が目的関数に一切現れず、最適化が同一校区への割当を無条件に優先する。実際には校区内でも徒歩 15 分程度の移動が生じる。

**費用を 0 とする理由**: 既定の距離帯モデルでも「2 km 未満 = 徒歩 = 0 円」であり、距離 0 km は必ず最下帯に属する。整合している。

---

### BR-D08: 距離帯の選択（排他的上限）

距離 `d` が属する帯は、**`d < upper_bound_km` を満たす最初の帯**である。

```text
帯 1: upper_bound_km = 2.0   →  0.0 <= d < 2.0
帯 2: upper_bound_km = 10.0  →  2.0 <= d < 10.0
帯 3: upper_bound_km = None  →  10.0 <= d
```

**上限は排他的、下限は包含的**である。境界値 `d = 2.0` は帯 2 に属する。

BR-D02 により最後の帯は `None`（無限大）であるため、**どの距離も必ずいずれかの帯に属する**。「該当する帯がない」という実行時エラーは構造的に発生しない。

## 3. エラー処理

### BR-D09: 存在しない小学校区への参照（Q6=A）

職員の居住小学校区 ID、または施設の所在小学校区 ID が、小学校区マスタに存在しない場合。

**`UnknownSchoolDistrictError` を送出する**（fail closed / SECURITY-15）。

**`None` を返さない理由**: 呼び出し元（U-04）が `None` を無視すると、**その職員が最適化から静かに脱落する**。誰も気づかないまま、割当結果に含まれない職員が生じる。

**例外を送出することで、距離行列の構築が失敗し、担当者にデータ不整合が報告される。**

**個人情報の扱い**: 例外の文脈属性には**小学校区 ID のみ**を含める。職員の氏名も、居住小学校区名も含めない（SECURITY-03）。

---

### BR-D10: 例外の一覧

| 例外 | 発生源 | 定義場所 |
|------|-------|---------|
| `InvalidCostModelError` | BR-D01, BR-D02, BR-D04 | U-01 `exceptions.py`（新規） |
| `UnknownSchoolDistrictError` | BR-D09 | U-01 `exceptions.py`（新規） |
| `InvalidTravelParametersError` | BR-D03 | U-01 `exceptions.py`（既存） |

**例外は U-01 に定義する。** U-02 は例外を送出するが、階層は U-01 が所有する（`DomainError` を基底とするため）。
