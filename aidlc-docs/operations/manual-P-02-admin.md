# 操作説明書 — P-02 システム管理者

**対象ペルソナ**: P-02 システム管理者（情報システム担当課 職員／例: 佐藤 美咲 主任）
**位置づけ**: マスタ・パラメータ・アカウント・アクセス制御・監査を担う**直接利用者**。
**前提知識**: CSV、ネットワーク設定、アクセス制御を理解している。
**参照**: `requirements.md` v1.3、`stories.md`（エピック E1/E3/E5）、`shared-infrastructure.md`、`personas.md`

> 本書は**要件定義に忠実に**、あなたの責務ごとに「何を・どの画面／どの手段で・どう実現するか」を示します。管理者の責務には、画面操作だけでなく**OS レベルの運用作業**（アカウント払い出し、IP 制限、監査ログ保全）が含まれます。各画面の詳細手順は別途の画面別説明書を参照してください。

## 2. マスタデータを維持する（エピック E3）

| あなたの目的 | 操作 | 画面 | 要件 | 実装状況 |
|-------------|------|------|------|---------|
| 職員マスタを一括更新する | 職員 CSV を取り込む／出力する | **マスタ画面** | US-07 | 実装済み |
| 施設マスタを一括更新する | 施設 CSV を取り込む／出力する | マスタ画面 | US-08 | 実装済み |
| 小学校区マスタを一括更新する | 小学校区 CSV を取り込む／出力する | マスタ画面 | US-09 | 実装済み |
| マスタの 1 レコードだけを個別修正する | 個別編集 | マスタ画面 | US-10 | **PoC対象外**（申し送り。当面は CSV 再取込で対応） |

**取り込み順序（重要）**: 施設は小学校区を参照するため、**小学校区 → 施設 → 職員** の順に取り込んでください。マスタ画面はこの順序で 3 つの取込パネルを提示します。

- **CSV エラー**: エラー行は行番号付きで表示されます（個人情報は含みません）。
- **エクスポートの安全性**: 出力 CSV は数式インジェクション対策として無害化されます（先頭が `=` 等のセルはエスケープ）。Excel で開いても数式として実行されません（MU-02）。
- **人事異動時**: 職員 CSV を差し替えて再取込することで一括更新できます（手作業を避けられます）。

> **個人情報の取り扱い**: 本システムは職員の**居住小学校区**という機微情報を扱います。氏名等は仮名化して扱う運用です（研修用 PoC）。データベース・監査ログは暗号化ボリューム上に置き、ログには ID のみを記録し氏名等は残しません。

## 3. 算出パラメータの初期値を設定する（エピック E5）

| あなたの目的 | 要件 | 実現手段 | 実装状況 |
|-------------|------|---------|---------|

- 目的関数の**重み**は割当担当者が最適化画面で都度指定します（US-17、P-01 の説明書参照）。

## 4. アカウントを管理する（エピック E1 / US-01）

| あなたの目的 | 実現手段 | 実装状況 |
|-------------|---------|---------|
| 利用者アカウントを発行・失効する | OS レベルの運用作業でアカウント（ユーザーID・パスワードハッシュ・ロール）を登録 | 運用作業（U06-H5） |

- 本 PoC には画面上のアカウント管理機能はありません（払い出しは OS レベルの運用作業と位置づけ、U06-H5）。
- パスワードは Argon2id でハッシュ化して保存されます（平文は保存されません）。
- ログイン失敗が続くと一時的にロックされます（総当たり対策）。

## 5. アクセス制御を維持する（エピック E1 / US-02）

| あなたの目的 | 実現手段 | 実装状況 |
|-------------|---------|---------|
| 庁内ネットワークからのみアクセス可能にする | **送信元 IP 許可リスト**（庁内出口 IP）を設定 | 実装済み（設定） |
| 公開基盤（TLS 終端・WAF）の背後で正しい送信元を判定する | **信頼プロキシ（`trusted_proxies`）** を設定 | 実装済み（設定） |

- **重要（デプロイ必須）**: 本システムは既存の公開基盤（TLS 終端・WAF）の背後で動作します。この場合、接続元アドレスはプロキシのものになるため、`trusted_proxies` に**そのプロキシを列挙**してください。
  - 未設定のまま公開基盤の背後に置くと、プロキシのアドレスが許可リスト判定に使われ**全アクセスが遮断**されます（安全側に倒れる設計＝誤って全開放にはなりません）。
- 認証・IP 制限・レート制限は**すべてのリクエストに先行して適用**されます。SPA（画面）の静的ファイルは認証なしで読み込めますが、**IP 制限は静的ファイルにも適用**されます（庁外からは画面自体が開けません）。

## 6. 監査ログを保全する（エピック E1 / US-03・US-04）

| あなたの目的 | 実現手段 | 実装状況 |
|-------------|---------|---------|
| 誰が何をいつ変更したかを追跡できるようにする | 割当変更等を監査ログに自動記録（ID のみ、PII なし） | 実装済み（自動） |
| 監査ログの改竄を防ぐ | 追記専用ファイル（`chattr +a`）+ OS 権限分離 | 実装済み（構造） |

- 監査ログは**追記専用**で、アプリ実行アカウントは追記のみ可能・削除不可です。ローテーション（日次・90 日保持）は権限を分けた別アカウントの cron が担います（`shared-infrastructure.md` §3）。
- 監査ログには**個人情報を含めません**（ID のみ）。

## 7. システムの起動・配信（運用手順）

詳細は `aidlc-docs/construction/build-and-test/build-instructions.md`。要点:

```bash
# API プロセス（U-01〜U-07 を含む）
uvicorn api_orchestration:build_application --factory --port 8000
# ジョブワーカー（最適化計算を別プロセスで実行）
python -m api_orchestration.worker
# フロントエンド（本番類似・単一サーバー配信）
cd src/frontend && npm run build   # dist/ を生成 → API プロセスが配信
```

- 最適化計算は最大 300 秒かかりうるため**別プロセス（ワーカー）**で実行し、API の応答性を保ちます。
- SQLite（PoC）/ PostgreSQL（実運用）を接続文字列の変更のみで切替可能です。

## 8. 本 PoC での制約（要点）

- **実装済み（あなたの操作）**: マスタ取込/出力（US-07/08/09）、IP 制限・信頼プロキシ設定（US-02）、監査（US-03/04、自動）。
- **設定で反映**: 算出パラメータ初期値（US-14）。
- **運用作業（画面外）**: アカウント払い出し（US-01／U06-H5）。
- **PoC対象外（申し送り）**: マスタ個別修正（US-10）、パラメータ設定 UI（US-14 の画面化）。
- **デプロイ時に必ず設定**: `trusted_proxies`（未設定=全遮断）、暗号化ボリューム、監査ログの `chattr +a` と cron。
