## 2. 該当する NFR

### NFR-U04-P01: 求解時間（性能、NFR-P02、中核）

**要件**: 最大規模（2,000 職員 × 200 施設 = 40 万 0-1 変数）で、既定の制限時間 300 秒以内に**実行可能解**を返す。

**達成手段**:
- OR-Tools CP-SAT（Q1=A）。0-1 割当に強い並列探索
- 時間制限を CP-SAT に設定。タイムアウト時は**最良実行可能解 + 最適性ギャップ**（Q2=A, FR-04.6）
- 変数枝刈りはしない（正しさ優先, Q3=A）

**検証**: **Build and Test** で代表データ（規模上限に近い）により実測。厳密最適に達しなくても、実行可能解 + ギャップを 300 秒以内に返すことを確認する。

---

### NFR-U04-R01: fail closed の求解（信頼性、SECURITY-15）

**要件**: ソルバーが不正な解を返しても、それを下流に流さない。

**達成手段**: すべての結果を `AssignmentResult.__post_init__`（BR-07）に通す。C3 以外の違反・非有限/負の目的値・重複割当を拒否（business-rules.md BR-OPT15）。

---

### NFR-U04-R02: 実行不可能時の診断（信頼性）

**要件**: 実行不可能でも推測で解を作らず、原因を明示する。

**達成手段**: 段階的求解の決定木（Functional Design Q4）。`InfeasibilityDiagnosis`（原因種別 + 施設/制約 ID、PII なし）を返す。

---

### NFR-U04-R03: 求解の再現性（信頼性、Q4=A）

**要件**: 同一入力・同一シードで再現可能な求解（保証範囲を明記）。

**達成手段**: `random_seed` と探索ワーカー数を固定。**保証範囲**: `OPTIMAL` または完了まで走った結果は再現可能。壁時計タイムアウトに依存する最良解は保証対象外。

---

### NFR-U04-P02: 非同期実行（性能インフラ、Q5=A）

**要件**: 300 秒の求解が API をブロックしない。

**達成手段**: U-01 の DB ベースジョブキューのワーカープロセスで実行（U-01 確定事項）。U-07 がジョブを配線する。

---

### NFR-U04-M01: ソルバー非依存の維持（保守性）

**要件**: ソルバー製品を差し替えても求解ロジックが不変であること。

**達成手段**: `SolverPort`（抽象、Functional Design）。CP-SAT アダプタが具象実装（U04-H6）。U-04 のサービスはポートに依存し製品に依存しない。

---

### NFR-U04-M02: オフライン動作（保守性、FR-03.6）

**要件**: 求解は外部 API に依存しない。

**達成手段**: OR-Tools はローカル求解ライブラリ。外部通信なし。Code Generation で確認（U04-H8）。

---

### NFR-U04-S01: サプライチェーン（セキュリティ、SECURITY-10）

**要件**: ソルバー依存を固定・監査する。

**達成手段**: `ortools` をバージョン固定、pip-audit 対象、SBOM に含める（U04-H8）。

---

### NFR-U04-S02: 個人情報の非露出（セキュリティ、SECURITY-03）

**要件**: 求解・診断・ログに個人情報を含めない。

**達成手段**: Functional Design で対応済み（BR-OPT17）。`InfeasibilityDiagnosis`・例外は ID のみ。
