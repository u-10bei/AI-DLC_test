### Question 1: MILP ソルバー製品の選定（Tech Stack, 申し送り H-3）

40 万 0-1 変数の一般化割当問題を、300 秒以内に実行可能解（できれば最適解）で解くソルバーを選定します。**庁内オンプレミス**で動作し、**ライセンス費用**を避けたい前提です。

A) **OR-Tools CP-SAT（Google, Apache-2.0, オープンソース）** — 0-1 割当・スケジューリング問題に極めて強い。線形目的・線形制約の整数モデルを扱える。**時間制限・最良実行可能解・最適性ギャップ（下界）をネイティブ対応**（FR-04.6/US-20 に合致）。並列探索、乱数シード対応。ライセンス費用なし、オンプレミス可。実運用実績多数 **（推奨）**

B) **PuLP + CBC（オープンソース）** — 純 Python モデリング + 同梱 CBC ソルバー。単純だが、CBC は 40 万 0-1 変数で 300 秒に収まらない可能性が高い（分枝限定が CP-SAT より弱い）

C) **商用ソルバー（Gurobi / CPLEX）** — 最高性能だが**ライセンス費用**が発生し、庁内オンプレミス PoC には不向き

### Question 2: 厳密解法 vs 発見的解法の戦略（性能, NFR-P02）

300 秒の制限時間内に厳密最適が出ない場合の戦略を確定してください。

A) **厳密ソルバー + 時間制限、タイムアウト時は最良実行可能解 + ギャップ** — 別途の発見的アルゴリズムを本 PoC では実装しない。CP-SAT は時間制限で**最良実行可能解と最適性ギャップに自然に劣化**する（FR-04.6）。Build & Test で代表データにより性能検証 **（推奨。単純かつ FR-04.6 に合致）**

B) **発見的解法（貪欲 + 局所探索）を主とする** — 高速だが最適性の保証・ギャップ提示が弱い

C) **ハイブリッド（小規模は厳密、大規模は発見的）** — 複雑。切替閾値の設計が必要

### Question 3: 問題サイズ削減（変数枝刈り）の是非（性能 vs 正しさ）

40 万は最悪ケースです。実際には各職員を遠方施設に割り当てる解は最適でないため、`x_ij` を距離で枝刈りする余地があります。

A) **本 PoC では枝刈りせず全変数でモデル化（正しさ優先）** — 最適解を除外しない。性能が不足する場合の枝刈り（職員ごとに近傍施設に候補を限定する等）は設定可能な最適化レバーとして**将来検討**。既定は無効 **（推奨、正しさ優先）**

B) **距離半径で枝刈り（高速化）** — 各職員の候補施設を近傍に限定。高速だが、最適解を除外しうる（準最適リスク）

### Question 4: 求解の再現性（信頼性, `random_seed`）

`OptimizationParameters.random_seed` があります。求解の再現性をどう扱いますか？

A) **乱数シードと探索ワーカー数を固定して再現性を確保。ただしタイムアウト時の最良解は実行環境で変わりうる旨を明記** — `OPTIMAL` 結果、または完了まで走った結果は再現可能。壁時計タイムアウトに依存する最良解は保証対象外とする **（推奨、正直な保証範囲）**

B) 再現性を保証しない — シードを固定しない
