# U-08 frontend — ビジネスルール（クライアント側検証）

**原則（Q5=A）**: クライアント側検証は **UX 目的の軽量チェックのみ**。真実の源はバックエンド。フロントの検証を通ってもバックエンドが `400`/`422` を返しうるため、フロントは常にバックエンドの応答メッセージを表示できるようにする。**フロントはバックエンドの全規則を写さない**（乖離を避ける）。

各ルールに `FE-*` の識別子を付す。「BE 相当」列は、フロント検証をすり抜けても最終的に守られるバックエンド側の根拠。

---

## 1. ログイン（V-01）

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-01 | `user_id` 非空 | 空送信の抑止 | LoginRequest min_length=1 |
| FE-02 | `password` 非空 | 同上 | LoginRequest min_length=1 |
| FE-03 | 認証失敗（`401`）は汎用文言「認証に失敗しました」を表示し、ユーザ存在有無を推測させない | 情報漏えい防止 | BR-SEC04（アカウント存在を明かさない） |

---

## 2. イベント作成（V-02）

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-10 | `id` 非空（1–32 文字） | 必須 | EventRequest 制約 |
| FE-11 | `name` 非空（1–100 文字） | 必須 | EventRequest 制約 |
| FE-12 | `type` は用意した日本語ラベルの選択肢から選ぶ（自由入力させない） | 未知ラベル 400 の抑止 | from_japanese（未知は 400, BR-DM03） |
| FE-13 | `scheduled_date` は日付として妥当 | 型エラー抑止 | date 型 |

---

## 3. CSV 取込（V-03 マスタ、V-04 申告）

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-20 | ファイル選択必須。拡張子 `.csv` を推奨表示（強制はしない） | 誤操作抑止 | — |
| FE-21 | 取込は生バイトを該当エンドポイントへ POST。整形・パースはフロントで行わない | バックエンドを真実の源に | csv_codec（U-03） |
| FE-22 | `400` + `errors[]` は行番号付きで全件表示（`line`, `message`）。PII は含まれない | US-07 の可観測性 | BR-DM02 / BR-DM14 |
| FE-23 | 成功時は `success_count` を表示 | フィードバック | ImportResultResponse |

## 4. 最適化パラメータ（V-06）

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-30 | 重み 3 つ（time/cost/inequity）は各 ≥ 0 | 範囲 UX | Field(ge=0.0) |
| FE-31 | **少なくとも 1 つの重み > 0**（全て 0 は不可） | BR-02 の事前提示 | ObjectiveWeights（全 0 は拒否, BR-02） |
| FE-32 | `time_limit_seconds` ≥ 1（整数） | 範囲 UX | Field(gt=0) |
| FE-33 | `department_cap_limit` ≥ 1（整数） | 範囲 UX | Field(gt=0) |
| FE-34 | `mode` は `FULL` / `INCREMENTAL` から選択。既定 `FULL` | US-24 | OptimizationRequest 既定 |
| FE-35 | ジョブ非終端の間は「実行」ボタンを無効化 | 多重投入防止 | ジョブキュー（条件付き claim） |

> 既定値は DTO と一致させる（time=1.0, cost=1.0, inequity=0.5, limit=300, cap=100）。

## 5. 割当の手動修正（V-07）

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-40 | `staff_id` / `facility_id` 非空 | 必須 | AssignmentPatchRequest 制約 |
| FE-41 | ハード制約の判定は**フロントで行わない**。PATCH の応答（`400` + `violations`）を表示する | 制約解釈の一元化（U07-H1） | validate_assignments（U-04 が唯一の解釈） |
| FE-42 | `violations` は制約 ID（例 C1/C5）と詳細、関係する施設・職員 ID を表示 | US-22 の可観測性 | ConstraintViolationResponse |

**重要**: C1〜C5 の制約はバックエンド（U-04）が唯一の解釈を持つ。フロントが二重に判定すると解釈が分岐するため、フロントは**送って結果を表示するだけ**にする。

---

## 6. 認証・セッション横断ルール

| ID | ルール | 目的 | BE 相当 |
|----|------|------|--------|
| FE-50 | 任意のリクエストが `401` を返したら V-01 へ遷移（セッション失効） | 失効の一貫処理 | 認証ミドルウェア（DP-01） |
| FE-51 | `403` は「この操作は許可されていません」を表示し、詳細は出さない | 認可失敗の非開示 | SEC-02 / SECURITY-09 |
| FE-52 | セッショントークンを JS で保持・保存しない（Cookie は HttpOnly） | XSS でのトークン窃取防止 | BR-API21 |
| FE-53 | バックエンドのエラーメッセージは加工せず表示（内部情報は元々含まれない） | SECURITY-09 の一貫適用 | ErrorResponse（内部を持たない） |

---

## 7. 適用外（意図的に持たないルール）

- 距離・時間・費用の計算ルール（U-02 が唯一の実装、NFR-M05 によりフロントは再実装しない）。
- 制約 C1〜C5 の充足判定（U-04 が唯一の解釈、FE-41）。
- 列挙値・日本語ラベルの対応表の再定義（U-01 が源、フロントはラベルを送るのみ）。
