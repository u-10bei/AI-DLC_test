## 2. 該当する NFR

### NFR-U07-P01: API は即応する（性能, Q3=A）

**要件**: 最大 300 秒の求解が API をブロックしない。

**達成手段**: `POST /optimizations` は `optimization_jobs` に投入して**即座に 202 + `job_id`** を返す。求解は**ワーカープロセス**（U-01 の決定）。

---

### NFR-U07-P02: 同期エンドポイントの実用性（性能, NFR-P01）

**要件**: 職員 2,000 / 施設 200 の規模で、イベント CRUD・割当一覧・充足集計が実用的に応答する。

**達成手段**: 重い処理は既に下位ユニットが目標を持つ（U-03 NFR-P04 / U-04 NFR-P02）。**U-07 固有の数値目標は設けない**。検証は Build and Test。

---

### NFR-U07-R01: ワーカーのプロセス分離（信頼性, Q2=A, U07-H4）

**要件**: 求解が API プロセスの資源を占有しない。

**達成手段**: CLI エントリポイント `python -m api_orchestration.worker`。常駐は systemd/supervisor（運用）。ポーリング間隔は外部化（既定 2 秒、NFR-M03）。1 ジョブずつ。

---

### NFR-U07-R02: fail closed（信頼性 / セキュリティ, SECURITY-15）

**要件**: 予期しない失敗が「通ってしまう」ことがない。

**達成手段**: BR-API07。ハンドラが把握しない例外は **500 + 汎用メッセージ**。ミドルウェアの各関門は U-06 の例外で拒否（deny by default）。ジョブの失敗は `FAILED`（`INFEASIBLE` とは区別）。

---

### NFR-U07-S01: セキュリティヘッダ（セキュリティ, SECURITY-04）

**要件**: HTML/HTTP を返すエンドポイントに CSP, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy を設定する。

**達成手段**: BR-API08。**U-07 が唯一 HTTP を返すユニット**であるため、本ルールは U-07 でのみ実効的。

---

### NFR-U07-S02: 入力検証（セキュリティ, SECURITY-05）

**要件**: すべての API エンドポイントで入力検証を行う。

**達成手段**: **Pydantic DTO**（検証済み: 不正な本文は 422）。SQL は U-03 が Core でパラメータ化済み。

---

### NFR-U07-S03: エラー応答（セキュリティ, SECURITY-09）

**要件**: 応答にスタックトレース・内部パス・フレームワークバージョンを含めない。

**達成手段**: BR-API06。グローバル例外ハンドラが汎用応答に変換。詳細は構造化ログ（PII なし）。

---

### NFR-U07-M01: 明示的な API 境界（保守性, NFR-M05, H-5）

**要件**: フロントエンドとバックエンドを、同一ホストでもプロセス内直接呼び出しで結合しない。

**達成手段**: BR-API03。境界は HTTP。バックエンド URL は設定外部化（U-08 側, U07-H6）。**実運用のオンプレミス分離をコード変更なしに行う**ため。

---

### NFR-U07-M02: ユニット境界（保守性, Q4=A）

**達成手段**: リンタ契約。**`pydantic`/`fastapi` を許可されるのは U-07 のみ**（他ユニットの契約が禁止＝境界が守られている証明）。`sqlalchemy` も許可（`SqlSessionStore`, U06-H2）。

---

### NFR-U07-S04: サプライチェーン（セキュリティ, SECURITY-10）

**達成手段**: `fastapi==0.115.6` / `uvicorn==0.34.0` / `pydantic==2.10.4` を固定、`httpx==0.28.1` は dev。pip-audit 対象、SBOM に含める（U07-H9）。

## 3. テスト戦略（Q5=A）

| 項目 | 決定 |
|------|------|
| HTTP 境界 | **FastAPI TestClient で実際に要求を送る。モックしない**——ミドルウェア順序・DTO 検証・例外ハンドラ・ヘッダは HTTP を通してしか検証できない（P-API02/03/04/06）|
| DB | インメモリ SQLite（U-03 のパターン）|
| ワーカー | テスト内で**同期的に 1 ステップ実行**（プロセスを起動しない）|
| **ステートフル（PBT-06）** | **必須**。ジョブ状態機械（`QUEUED→RUNNING→終端`、終端から遷移しない）|
| プロパティ | P-API01〜07 |
