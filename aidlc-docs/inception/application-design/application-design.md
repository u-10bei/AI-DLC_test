| # | 判断 | 選択 | 根拠 |
|---|------|------|------|
| 1 | アーキテクチャスタイル | **ヘキサゴナル（ポート＆アダプタ）** | NFR-M01（ソルバー差し替え）と NFR-M02（純粋関数）を構造として強制できる |

| 10 | セキュリティ統制 | **専用モジュール群に集約** | SECURITY-11 |

## 3. この設計が解決する主要な課題

### 3.1 最適化アルゴリズムの差し替え可能性（NFR-M01）

ソルバーは `P-01 SolverPort` の背後のアダプタである。NFR Requirements ステージで厳密解法（MILP）の性能が不十分と判明した場合、`A-03b HeuristicSolverAdapter` を実装して差し替えるだけでよい。ドメイン層とサービス層は変更しない。

**副次的な利益**: テスト時に `A-03c BruteForceSolverAdapter`（総当たり法）へ差し替えることで、オラクル検証（PBT-05、INV-12）が**プロダクションコードを変更せずに**実現できる。小規模インスタンス（職員 10 名、施設 3 か所）で厳密解法の出力と比較する。

### 3.2 300 秒の計算と HTTP タイムアウトの両立

非同期ジョブ + ポーリング（Q2=B）により、計算時間を HTTP のライフサイクルから切り離す。`JobStatus` が経過時間・現在の目的関数値・最適性ギャップを含むため、US-20（制限時間到達時に最良解と最適性ギャップを提示する）が自然に実現できる。

### 3.3 実行不可能時の原因診断（FR-04.5）

`C-04 InfeasibilityDiagnoser`（純粋関数）が原因を診断し、`S-04 OptimizationService`（オーケストレーション）が結果に応じて分岐する。

| 診断 | 措置 |
|------|------|
| 従事可能職員の**総数不足** | 起動を拒否し、不足人数と不足施設を提示する。**C1（定員充足）は決して緩和しない**。追加申告を求める |
| **C3（職種・資格・役職）の不足のみ** | C3 をソフト制約に降格し、ビッグMペナルティを課して解を求める。違反箇所を一覧表示しハイライトする |
| C2, C4, C5 による実行不可能 | 原因を提示するのみ。**降格しない**（C2 は物理的に不可能、C4 は休暇中・健康配慮の職員の派遣、C5 は部署の業務停止を意味するため） |

診断ロジックが純粋関数であるため、DB もジョブキューも持たずにテストできる。

### 3.4 比較レポートの妥当性（SC-01）

`S-06 ComparisonReportService` は最適化ロジックを持たず、`S-04 OptimizationService` に委譲する。したがって、レポートが示す削減効果は、**システムが実際に生成する割当**を反映する。別実装で計算した数値を上長に提示する事態を、構造として防ぐ。

### 3.5 監査ログの改竄防止（SECURITY-14）

`P-04 AuditLogPort` に削除・更新のメソッドを**定義しない**。アプリケーションコードから監査ログを削除する経路が、型レベルで存在しない。US-04 の受入基準を構造として保証する。

さらに、監査ログの書き込みは業務トランザクションの外側で行う。業務操作がロールバックされても「変更を試みた」事実は記録に残る。

### 3.6 実運用への移行（申し送り H-8）

| 項目 | PoC | 実運用 | 設計上の備え |
|------|-----|--------|-------------|
| デプロイ構成（A-07） | フロント・バックが同一サーバーに同居 | バックエンドを庁内オンプレミスへ分離 | **NFR-M05**: 同居していても通信は必ず REST API 経由。プロセス内直接呼び出しを禁止。エンドポイント URL は設定として外部化 |
| 従事可否の入力主体（A-08） | 担当者が代理で CSV 一括登録 | 職員本人がログインして申告 | **FR-02.7**: 従事可否申告を独立エンティティとする。**SEC-02** のオブジェクトレベル認可を先行して用意する |

## 4. 拡張ルール適合サマリ

### 4.1 Security Compliance（security/baseline — 有効）

| ルール | 判定 | 根拠 |
|--------|------|------|
| SECURITY-01 暗号化 | **N/A** | Infrastructure Design / Code Generation で検証する。本ステージに設計面の表出がない |
| SECURITY-02 中継機器のアクセスログ | **N/A** | Infrastructure Design で検証する（申し送り H-6） |
| SECURITY-03 アプリケーションログ | **適合** | `P-04 AuditLogPort` の `AuditEntry` に「個人情報を含めない。職員 ID のみ」というビジネスルールを明記した |
| SECURITY-04 HTTP セキュリティヘッダ | **適合** | `A-01 RestApiAdapter` の責務として明記した。具体的なヘッダ値は NFR Design で定義する |
| SECURITY-05 入力検証 | **適合** | `SEC-05 InputValidationModule` を全リクエストのミドルウェア連鎖に組み込んだ。`A-02 PersistenceAdapter` はパラメータ化クエリのみを使用する |
| SECURITY-06 最小権限 | **N/A** | Infrastructure Design で検証する。IAM ポリシーは本ステージの対象外 |
| SECURITY-07 ネットワーク構成 | **適合（文書化された例外の代償統制）** | `SEC-03 NetworkControlModule` が庁内出口 IP の許可リストを検証する。許可リストは `P-06 ConfigPort` から取得しハードコードしない。具体設計は Infrastructure Design で検証する |
| SECURITY-08 アプリケーション層の認可 | **適合** | `SEC-02 AuthorizationModule` が deny by default の認可ガードとオブジェクトレベル認可を提供する。公開エンドポイントの免除リストはコード上の 1 か所に集約する |
| SECURITY-09 ハードニング | **適合** | エラー応答にスタックトレース・内部パス・フレームワークバージョンを含めない旨を `services.md` セクション 6 に明記した |
| SECURITY-10 サプライチェーン | **N/A** | NFR Requirements / Build and Test で検証する |
| SECURITY-11 セキュアデザイン | **適合** | セキュリティロジックを SEC-01〜SEC-05 の専用モジュールに隔離した（Q10=A）。`SEC-04 RateLimitModule` が公開エンドポイントにレート制限を課す。4 件の誤用シナリオ（MU-01〜MU-04）への統制を設計に反映した（下記 4.3） |
| SECURITY-12 認証と資格情報管理 | **適合** | `SEC-01 AuthenticationModule` がサーバー側セッション、Cookie の Secure/HttpOnly/SameSite、適応型ハッシュ、アカウントロックを担う |
| SECURITY-13 ソフトウェアとデータの完全性 | **適合** | `S-08 AuditService` が割当結果の変更を実行者・日時・変更前後の値とともに記録する |
| SECURITY-14 アラートと監視 | **適合** | `P-04 AuditLogPort` に削除・更新メソッドを定義しない。監査ログは業務 DB とは別の追記専用ストレージへ書き込む。`S-08.recordSecurityEvent` が認証失敗・認可違反・IP 拒否・アカウントロックを記録する。保持期間とアラート閾値は Infrastructure Design で定義する |
| SECURITY-15 例外処理と fail-safe | **適合** | CSV インポートは 1 行でもエラーがあれば全体をロールバックする（fail closed）。ミドルウェア連鎖のいずれの拒否も汎用エラーを返す |

### 4.3 誤用・悪用シナリオへの統制（SECURITY-11、申し送り H-7）

|---------|------|------|

## 6. Units Generation ステージへの引き渡し

本設計は、以下の**ユニット候補**を示唆する。確定は Units Generation ステージで行う。

| ユニット候補 | 含まれるコンポーネント | 特性 | 依存 |
|-------------|---------------------|------|------|
| **距離・費用算出** | C-01, P-03, A-02（キャッシュ部分） | 純粋関数。数学的性質の検証（INV-07〜INV-09） | なし |
| **最適化エンジン** | C-02, C-03, C-04, P-01, A-03, A-03b, A-03c | アルゴリズム的中核。オラクル検証（PBT-05） | 距離・費用算出 |
| **データ管理** | S-01, S-02, S-03, P-02, P-07, A-02, A-04 | CRUD + CSV。トランザクション整合性 | なし |
| **比較レポート** | C-05, S-06 | 集計と出力 | 最適化エンジン、データ管理 |
| **Web UI / API・セキュリティ** | F-01, A-01, SEC-01〜05, S-04, S-05, S-07, S-08, P-04, P-05, P-06, A-01, A-05, A-06, A-07 | 認証・認可・入力検証・ジョブ調整 | 全ユニット |

**依存の順序**: 距離・費用算出 → 最適化エンジン → 比較レポート。データ管理は独立。Web UI / API は最後。
