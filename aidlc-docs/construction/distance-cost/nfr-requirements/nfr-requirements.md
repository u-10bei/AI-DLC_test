## 2. 該当する NFR

### NFR-U02-P01: 距離行列の計算性能（性能）

**要件**: 小学校区数 200（キャッシュエントリ 20,100）に対する距離行列の計算を、1 秒以内に完了する。

**達成手段**: 標準ライブラリ `math` による素朴なループ（Q1=A）。NumPy を使わない。Haversine 1 回は三角関数を数回呼ぶのみで、2 万回でも 1 秒未満。

**検証**: Build and Test ステージで、200 校区の距離行列計算時間を実測する。

---

### NFR-U02-P02: キャッシュによる再計算の回避（性能）

**要件**: 迂回係数・平均速度・費用モデルの変更（US-14）では、距離行列を再計算しない。

**達成手段**: キャッシュには**大円距離のみ**を保存する（U-02 Functional Design Q3=A）。大円距離は小学校区の代表点座標のみに依存するため、上記パラメータの変更では無効化されない。

**無効化の契機**: 小学校区マスタの更新時のみ（US-09）。

---

### NFR-U02-R01: fail closed の生成時バリデーション（信頼性）

**要件**: 不正な `CostBand` / `CostModel` / `TravelParameters` は生成を拒否する。存在しない小学校区への参照は例外を送出する。

**達成手段**: BR-D01〜BR-D04（費用モデルの検証、特に単調非減少性）、BR-D09（`UnknownSchoolDistrictError`）。`None` を返して呼び出し元の判断に委ねない。

**根拠**: SECURITY-15。呼び出し元（U-04）が `None` を無視すると、その職員が最適化から静かに脱落する。

---

### NFR-U02-R02: 費用関数の単調非減少性（信頼性）

**要件**: 費用関数は距離に対して単調非減少でなければならない。違反する距離帯設定は拒否する。

**達成手段**: `CostModel` の生成時検証（BR-D04）と、`travel_cost_yen` の出力を検証するプロパティ（P-D01）の二重防御。

**根拠**: 「遠くへ行くほど安くなる」設定を許すと、最適化がより遠い施設への派遣を選び、プロジェクトの目的に反する。

---

### NFR-U02-M01: 費用モデルの差し替え可能性（保守性）

**要件**: 費用モデルを、線形・距離帯・その他（将来の旅費支給規程）へ差し替え可能にする。

**達成手段**: 費用モデルは `CostModel`（U-01 の値オブジェクト）として抽象化済み。`travel_cost_yen(distance, cost_model)` は `cost_model` を引数に取る。**モデルの変更は `CostModel` の構築を変えるだけで済み、`travel_cost_yen` のロジックは変わらない。**

---

### NFR-U02-M02: 純粋関数性の機械的強制（保守性、NFR-M02）

**要件**: U-02 のプロダクションコードは純粋関数のみで構成する。副作用・外部依存を持たない。

**達成手段**:
- リンタ規則 **R-3**: `src/distance_cost/` は `src/shared_kernel/` 以外を import してはならない
- 新規契約「`distance_cost` は標準ライブラリのみ」: `sqlalchemy`, `numpy` 等を import できない

**この 2 契約により、U-02 が DB もネットワークも時刻も参照できない構造が保証される。** INV-07〜INV-09 のプロパティテストがモックを一切必要としない理由である。

---

### NFR-U02-S01: 個人情報を扱わない（セキュリティ）

**要件**: U-02 は個人情報にアクセスしない。

**達成手段（構造による保証）**: U-02 の入力は小学校区 ID と座標のみである。職員の氏名も居住小学校区名も参照しない。リンタ規則 R-3 により、`Staff` エンティティに到達する経路が存在しない（`shared_kernel` 経由でも、U-02 が使うのは `SchoolDistrict` と `Coordinates` のみ）。

`UnknownSchoolDistrictError` の文脈属性には**小学校区 ID のみ**を含める（SECURITY-03）。

## 4. NFR-M02 の再確認

U-02 が純粋関数であることは、**Code Generation ステージで `.importlinter` に 2 つの契約を追加することで機械的に保証する**。

1. **R-3**: `distance_cost` は `shared_kernel` 以外のユニットを import してはならない
2. **新規**: `distance_cost` は標準ライブラリのみを使う（`numpy`, `sqlalchemy` 等を禁止）

**U-01 で `import pydantic` の混入により契約の実効性を確認したのと同様に、U-02 でも `import numpy` の混入で契約が BROKEN になることを確認する。**
