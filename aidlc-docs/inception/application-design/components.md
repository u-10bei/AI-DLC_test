# コンポーネント定義（Components）

**作成日**: 2026-07-09
**ステージ**: INCEPTION - Application Design
**アーキテクチャスタイル**: ヘキサゴナルアーキテクチャ（ポート＆アダプタ）— Q1=B

---

## 1. アーキテクチャの原則

### 1.1 依存の方向

**依存は常に外側から内側へ向かう。ドメイン層は何にも依存しない。**

```text
        +-------------------------------------------------------+
        |                  ADAPTERS (外側)                      |
        |  REST API / DB / Solver / CSV / Audit Store / Job     |
        +-------------------------------------------------------+
                              |  implements
                              v
        +-------------------------------------------------------+
        |                    PORTS (境界)                       |
        |  SolverPort / RepositoryPort / AuditLogPort / ...     |
        +-------------------------------------------------------+
                              ^  defined by, depends on
                              |
        +-------------------------------------------------------+
        |              APPLICATION SERVICES (中間)              |
        |  Orchestration / Transaction / Job coordination       |
        +-------------------------------------------------------+
                              |  uses
                              v
        +-------------------------------------------------------+
        |                    DOMAIN (中心)                      |
        |  Entities / Pure functions / Constraints / Diagnosis  |
        |  外部への依存を一切持たない                           |
        +-------------------------------------------------------+
```

### 1.2 この構造が保証する非機能要件

| 要件 | 保証方法 |
|------|---------|
| **NFR-M01**（最適化アルゴリズムの差し替え可能性） | ソルバーは `SolverPort` の背後のアダプタである。ドメインとサービス層は具体的なソルバーを知らない。厳密解法アダプタと発見的解法アダプタを差し替えても、内側のコードは変更されない |
| **NFR-M02**（距離算出の純粋関数性） | `DistanceCostCalculator` はドメイン層の内側に位置し、ポートを一切持たない。DB もファイルも時刻も参照できない構造である |
| **NFR-M05**（明示的な API 境界） | フロントエンドは REST アダプタを介してのみバックエンドに到達する。同一ホストに同居していても、プロセス内の直接呼び出しは構造上不可能である |
| **SECURITY-11**（セキュリティロジックの隔離） | 認証・認可・レート制限・入力サニタイズは専用のセキュリティモジュール群に集約される |

## 2. ドメイン層（Domain）

**外部への依存を一切持たない。副作用を持たない。テストにモックを必要としない。**

---

### C-01: DistanceCostCalculator（距離・費用算出）

**目的**: 小学校区の代表点間の距離、移動時間、移動費用を算出する。

**責務**:
- 2 つの小学校区の代表点間の大円距離（Haversine 距離）を算出する
- 直線距離に迂回係数を乗じて実移動距離を近似する
- 実移動距離を平均移動速度で除して移動時間を算出する
- 同一小学校区の場合、移動時間を固定値とする
- 実移動距離に距離単価を乗じて移動費用を算出する

**特性**: **純粋関数のみで構成する**（NFR-M02）。副作用を持たず、外部 API・DB・時刻・乱数を参照しない。

**インターフェース**: 座標とパラメータを受け取り、距離・時間・費用を返す関数群。

**関連ストーリー**: US-15
**関連不変条件**: INV-07（対称性）、INV-08（非負性、同一校区固定値）、INV-09（迂回係数の単調性）
**関連要件**: FR-03.1〜FR-03.6

---

### C-02: AssignmentDomainModel（割当ドメインモデル）

**目的**: 割当問題のエンティティと値オブジェクトを定義する。

**責務**:
- エンティティを定義する: `Event`, `Staff`, `Facility`, `SchoolDistrict`, `AvailabilityDeclaration`, `Assignment`, `AssignmentResult`, `HistoricalRecord`
- 値オブジェクトを定義する: `Coordinates`, `TravelMetrics`, `ObjectiveWeights`, `OptimizationParameters`
- 割当問題（`AssignmentProblem`）を、制約と目的関数を含む形で構成する

**重要な設計判断**: `AvailabilityDeclaration`（従事可否申告）は `Staff` の属性ではなく、`(Staff, Event)` の組に対する独立したエンティティである（FR-02.7）。同一職員が複数イベントに異なる申告を行える。

**関連ストーリー**: US-11, US-12, US-16
**関連要件**: FR-02.7, FR-04.1

---

### C-03: ConstraintValidator（制約検証）

**目的**: 与えられた割当が制約を満たすかを検証する。

**責務**:
- ハード制約 C1（定員充足）、C2（一意割当）、C3（職種・資格・役職）、C4（従事可否）、C5（部署継続性）への違反を検出する
- 違反の内容（どの制約が、どの施設・職員について、何件違反しているか）を構造化して返す
- ソフト制約 S1（従事履歴の平準化）の違反ペナルティを算出する

**特性**: 純粋関数。副作用を持たない。

**利用箇所**:
- 最適化結果の検証（US-16）
- 手動修正時の即時検証（US-22、FR-06.3）
- ピン留めの妥当性検証（US-23、FR-06.4）
- C3 降格時の違反一覧生成（US-19、FR-04.5.1）

**関連不変条件**: INV-01〜INV-04
**関連要件**: FR-04.3, FR-04.4, FR-06.3, FR-06.4

---

### C-04: InfeasibilityDiagnoser（実行不可能性の診断）

**目的**: 最適化が実行不可能な場合、その原因を診断して分類する。

**責務**（FR-04.5）:
- **総数不足**を検出する: 従事可能と申告した職員数 < 必要人数の総和
- **C3 不足**を検出する: 総数は足りているが、特定施設の資格要件を満たす職員が足りない
- **その他の制約（C2, C4, C5）による実行不可能**を検出する
- 診断結果に基づき、取るべき措置（追加申告の要求 / C3 のソフト化 / 原因の提示のみ）を返す

**重要な設計判断**: **C1（定員充足）は決してソフト化しない**。総数不足の場合、定員割れの解を返してはならない（US-18）。ソフト化を許容するのは **C3 のみ**であり、ビッグMペナルティを課す（CQ1=B, CQ2=C）。

**特性**: 純粋関数。副作用を持たない。

**関連ストーリー**: US-13, US-18, US-19
**関連不変条件**: INV-02（総数不足時に C1 を緩和した解を返さない）、INV-12（ビッグMによる C3 優先）
**関連要件**: FR-04.5

---

### C-05: ComparisonAnalyzer（比較分析）

**目的**: ベースライン割当と最適化割当の差分を算出する。

**責務**:
- 過去イベントの実績から、各施設の必要人数を導出する（実績の割当人数、FR-05.1.2）
- 過去イベントの従事可能職員集合を特定する（従事可能と申告した職員、FR-05.1.3）
- 総移動時間・総移動費用・最大移動時間の削減量と削減率を算出する
- 移動時間の分布（ヒストグラム、分位点）を算出する

**重要な設計判断**: **本コンポーネントは最適化ロジックを持たない**（Follow-up Q1=A）。最適化そのものは、実際の割当で使われるのと同一の共有エンジンにサービス層経由で委譲する。これにより、レポートが示す削減効果は、システムが実際に生成する割当を反映する（SC-01 の妥当性）。

**特性**: 純粋関数。副作用を持たない。

**関連ストーリー**: US-26, US-27
**関連要件**: FR-05.1.2, FR-05.1.3, FR-05.2

## 3. ポート（Ports）

**ドメイン層またはサービス層が定義するインターフェース。実装はアダプタが提供する。**

| ポート | 目的 | 実装するアダプタ |
|-------|------|----------------|
| **P-01 SolverPort** | 割当問題を受け取り、解と最適性ギャップを返す | A-03 ExactSolverAdapter, A-03b HeuristicSolverAdapter |
| **P-02 RepositoryPort** | エンティティの永続化と取得（Event, Staff, Facility, SchoolDistrict, AvailabilityDeclaration, Assignment, HistoricalRecord ごとに分割） | A-02 PersistenceAdapter |
| **P-03 DistanceCachePort** | 小学校区ペア単位の距離キャッシュの読み書き（Q4=A） | A-02 PersistenceAdapter |
| **P-04 AuditLogPort** | 監査ログの追記（読み取り専用の参照は別メソッド。削除・更新のメソッドを**定義しない**） | A-05 AuditLogAdapter |
| **P-05 JobStorePort** | 非同期ジョブの登録、状態取得、キャンセル要求（Q2=B, Q3=A） | A-06 JobRunnerAdapter |
| **P-06 ConfigPort** | 迂回係数、平均移動速度、距離単価、同一校区固定時間、目的関数の重み、部署別上限人数、IP 許可リストの取得（NFR-M03） | A-07 ConfigAdapter |
| **P-07 CsvCodecPort** | CSV の解析と直列化 | A-04 CsvAdapter |

**設計判断（SECURITY-14）**: `AuditLogPort` は削除・更新のメソッドを**定義しない**。アプリケーションコードから監査ログを削除する経路が、型レベルで存在しない。これは US-04 の受入基準「アプリケーションが監査ログの削除を試みると失敗する」を、構造として保証する。

## 4. アプリケーションサービス層（Application Services）

**オーケストレーション、トランザクション境界、ジョブ調整を担う。ビジネスルールそのものは持たない。**

| サービス | 目的 | 関連ストーリー |
|---------|------|--------------|
| **S-01 EventService** | イベントの登録・編集・削除・ステータス管理 | US-05, US-06 |
| **S-02 MasterDataService** | 職員・施設・小学校区マスタの CSV 一括インポートと個別修正。インポートは fail closed（1 行でもエラーなら全体ロールバック） | US-07, US-08, US-09, US-10 |
| **S-03 AvailabilityService** | 従事可否申告の一括登録、再申告と履歴管理、充足状況の集計 | US-11, US-12, US-13 |
| **S-04 OptimizationService** | 最適化ジョブの起動・監視・キャンセル。実行不可能時の原因診断分岐（C-04 に委譲）。C3 のソフト化判断 | US-16, US-17, US-18, US-19, US-20 |
| **S-05 AssignmentAdjustmentService** | 割当結果の参照、手動修正、ピン留め、再最適化モードの選択 | US-21, US-22, US-23, US-24, US-25 |
| **S-06 ComparisonReportService** | 過去イベント実績の取り込み、ベースライン再現の条件組み立て、**最適化を S-04 に委譲**、比較レポートの生成 | US-26, US-27, US-28 |
| **S-07 ConfigService** | 算出パラメータと目的関数の重みの取得・更新 | US-14 |
| **S-08 AuditService** | 監査ログの記録。個人情報を含めない | US-03, US-04 |

## 5. セキュリティモジュール群（Security Modules）

**SECURITY-11 に基づき、セキュリティ上重要なロジックを専用モジュールに隔離する（Q10=A）。**

各モジュールは、他のコンポーネントから利用される横断的関心事である。

| モジュール | 責務 | 対応する誤用シナリオ / ルール |
|-----------|------|---------------------------|
| **SEC-01 AuthenticationModule** | サーバー側セッションの発行・検証・失効（Q5=A）。Cookie に Secure / HttpOnly / SameSite を設定。パスワードの適応型ハッシュ。ログイン失敗の連続検出とアカウントロック | MU-03、SECURITY-12、US-01 |
| **SEC-02 AuthorizationModule** | **deny by default** の認可ガード。明示的に公開と指定されたエンドポイント以外はすべて認証を要求する。リソース ID を参照する要求では、呼び出し元の権限をサーバー側で検証する（オブジェクトレベル認可） | MU-01、SECURITY-08、US-01 |
| **SEC-03 NetworkControlModule** | 送信元 IP アドレスの許可リスト検証。庁内イントラネットの出口グローバル IP 以外を拒否する。許可リストは設定として外部化する（NFR-M03） | SECURITY-07 の代償統制、NFR-S10.2、US-02 |
| **SEC-04 RateLimitModule** | 公開エンドポイントへのレート制限 | MU-03、SECURITY-11 |
| **SEC-05 InputValidationModule** | 型検査、長さ上限、書式の許可リスト検証。リクエストボディのサイズ上限。**CSV エクスポート時の数式インジェクション無害化** | MU-02、SECURITY-05 |

**設計判断**: SEC-05 の「CSV エクスポート時の数式インジェクション無害化」は、A-04 CsvAdapter が SEC-05 を利用する形で実現する。CSV の値が `=`, `+`, `-`, `@` で始まる場合、エクスポート時にエスケープする。

## 6. アダプタ層（Adapters）

**ポートの実装。外部世界（HTTP、DB、ソルバー、ファイル）との接続を担う。**

| アダプタ | 実装するポート | 責務 |
|---------|--------------|------|
| **A-01 RestApiAdapter** | （なし。駆動側アダプタ） | HTTP リクエストを受け取り、サービス層を呼び出す。SEC-01〜SEC-05 をミドルウェアとして適用する。HTTP セキュリティヘッダを設定する（SECURITY-04） |
| **A-02 PersistenceAdapter** | P-02 RepositoryPort, P-03 DistanceCachePort | エンティティの永続化。パラメータ化クエリのみを使用する（SECURITY-05）。トランザクション境界を提供する |
| **A-03 ExactSolverAdapter** | P-01 SolverPort | 厳密解法（MILP ソルバー）による求解。制限時間と最適性ギャップを扱う |
| **A-03b HeuristicSolverAdapter** | P-01 SolverPort | 発見的解法による求解。**NFR Requirements ステージの評価結果次第で実装する**（H-3） |
| **A-03c BruteForceSolverAdapter** | P-01 SolverPort | 総当たり法。**テスト専用のオラクル**（PBT-05、INV-12 の検証） |
| **A-04 CsvAdapter** | P-07 CsvCodecPort | CSV の解析と直列化。SEC-05 を利用して数式インジェクションを無害化する |
| **A-05 AuditLogAdapter** | P-04 AuditLogPort | 業務 DB とは別の追記専用ストレージへの書き込み（Q6=A）。アプリケーションのアカウントに削除権限を与えない |
| **A-06 JobRunnerAdapter** | P-05 JobStorePort | バックグラウンドでの最適化ジョブ実行。ジョブ状態（待機中 / 実行中 / 完了 / 失敗 / キャンセル済み）の管理。同一イベントにつき同時 1 ジョブの制御（Q3=A） |
| **A-07 ConfigAdapter** | P-06 ConfigPort | 設定値の読み込み。ハードコードを禁止する（NFR-M03） |

**A-03c BruteForceSolverAdapter の設計的価値**: ヘキサゴナルアーキテクチャの採用により、オラクル検証（PBT-05）が**アダプタの差し替えだけで実現できる**。テスト時に `SolverPort` の実装を総当たり法に差し替え、小規模インスタンス（職員 10 名、施設 3 か所）で厳密解法の出力と比較する。プロダクションコードに変更を加える必要がない。

## 7. フロントエンド（Frontend）

**F-01 WebFrontend**

- 割当担当者（P-01）とシステム管理者（P-02）が操作する画面
- バックエンドとは **REST（JSON over HTTP）** でのみ通信する（Q8=A）
- バックエンドのエンドポイント URL は設定として外部化する（NFR-M05）
- 最適化ジョブの進捗をポーリングで取得する（Q2=B）

**NFR-M05 の遵守**: PoC ではフロントエンドとバックエンドが同一サーバー上で稼働するが（A-07）、通信は必ず REST API を経由する。プロセス内の直接呼び出しを行ってはならない。これにより、実運用でバックエンドをオンプレミスへ分離する際、コード変更を要さない。

## 8. PoC と実運用の差異（申し送り H-8）

| 項目 | PoC | 実運用 | 設計上の備え |
|------|-----|--------|-------------|
| デプロイ構成（A-07） | フロントエンドとバックエンドが同一のインターネット側サーバーに同居 | バックエンドを庁内オンプレミスへ分離 | NFR-M05: REST API 境界と、外部化されたエンドポイント URL |
| 従事可否の入力主体（A-08） | 割当担当者が代理で CSV 一括登録 | 職員本人がログインして申告 | FR-02.7: 従事可否申告を独立エンティティとする。SEC-02 のオブジェクトレベル認可により、職員が他人の申告を閲覧・改竄できない構造を先行して用意する |
| ペルソナ P-03（従事職員） | 間接的受益者。システムを直接操作しない | 直接利用者 | SEC-01 のアカウント管理は 500〜2,000 人規模への拡張を想定する |
