# U-08 frontend — Infrastructure Design：検証済みスキップ（1 finding）

**ユニット**: U-08 frontend
**判断**: **スキップ**（前提: ユーザ承認）。ただし**思い込みのスキップではなく検証済み**。`shared-infrastructure.md` を実際に読み、フロント固有のインフラ面を 1 つずつ確認した。
**日付**: 2026-07-23

---

## 1. 検証の経緯

`shared-infrastructure.md` は「拘束範囲: U-01〜U-07、**U-08 frontend は別途**」と明記している（同 §で U-08 を除外）。したがって「共有インフラに書いてあるから不要」と機械的に結論づけず、フロント固有の 7 カテゴリを個別に確認した。

同ドキュメントの PoC サーバー構成図（§1.1）には、**Frontend (U-08) が同一の PoC サーバー上に、公開基盤（TLS 終端・アクセスログ・WAF・IP 許可リスト）の背後に配置**されることが既に図示されている。

## 2. カテゴリ別の確認結果

| カテゴリ | 状態 | 根拠 |
|---------|------|------|
| **デプロイ先** | 確定済み | 同一 PoC サーバー（A-07）。図 §1.1 に Frontend (U-08) が明示 |
| **ネットワーク／TLS／WAF** | 確定済み（U-01 で解決） | 公開基盤が TLS 終端・アクセスログ・WAF を提供（H-6 解消済み、§1.2） |

| **ストレージ／DB** | **持たない** | 状態はバックエンドの `app.db`。フロントは永続ストレージを持たない |
| **クラウドリソース** | **なし** | 新規のマネージドリソース・キュー・キャッシュサーバなし（NFR Design でインフラ系論理コンポーネントなしと確定） |

7 カテゴリすべてが「確定済み」または「持たない」。**フロント独自に新規設計すべきインフラは存在しない。**

---

## 3. FINDING（1 件）: 静的バンドルの配信方法

図はフロントが同一サーバーで配信されることを示すが、**「どのように配信するか」は shared-infrastructure.md では特定されていない**（同ドキュメントは U-08 を範囲外とするため）。選択肢:

- (a) バックエンドの uvicorn プロセスが静的ファイルを配信（例: FastAPI `StaticFiles` でビルド済みバンドルを mount）
- (b) 独立した軽量静的ファイルサーバー

**評価**: これは**新規インフラの設計を要する事項ではなく、Code Generation の実装詳細**である。理由:
- どちらでも新規のコンピュート／ストレージ／クラウドリソースは増えない（同一サーバー内の配信手段の違い）。
- (a) を選んでも **NFR-M05 は侵さない**: 静的アセットの配信と、フロント→バックエンドの REST 通信は別物であり、プロセス内の直接呼び出し（ドメイン／サービスの共有）は発生しない。フロントは依然として REST のみでバックエンドと通信する。
- H-5（フロント→バックエンド import 禁止）は配信手段と独立に、フロントのビルド／lint（LC-FE-07）で強制される。

**記録**: 配信方法（(a) 推奨: PoC で最小構成）は **U-08 Code Generation で確定**する。実運用でバックエンドをオンプレミス分離する際は、フロントの配信も分離しうるが、NFR-M05 により無変更（§1.3）。これを **U08-H4** として申し送る。

---

## 4. 結論

U-08 frontend の Infrastructure Design は**スキップ**が妥当。7 カテゴリは確定済み／該当なしで、新規インフラ設計は不要。唯一の未特定事項（静的配信方法）は Code Generation の実装詳細であり、独立したインフラ設計ステージを要しない（U08-H4 として記録）。

**申し送り継続**: U08-H1（施設・小学校区エンドポイント）、U08-H2（AssignmentResponse 移動指標）、U08-H3（比較画面は U05-H6 後）、**U08-H4（静的配信方法は Code Generation で確定）**、H-5（LC-FE-07 で強制）。
