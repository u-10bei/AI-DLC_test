## 2. 該当する NFR

### NFR-U03-P01: CSV 一括インポートの性能（性能、NFR-P04）

**要件**: CSV 2,000 行のインポート（解析 + 検証 + 保存）を 30 秒以内に完了する。

**達成手段**:
- 解析: 標準ライブラリ `csv`（2,000 行で 1 秒未満、Q1=A）
- 保存: SQLAlchemy Core の `executemany`（一括 INSERT、数百ミリ秒、Q2=A）
- 全体を 1 トランザクション内で実行（fail closed の原子性を保つ）

**検証**: Build and Test で 2,000 行の実測。

---

### NFR-U03-P02: 距離キャッシュによる再計算回避（性能、NFR-P03）

**要件**: 迂回係数・平均速度・費用モデルの変更では距離キャッシュを再計算しない。

**達成手段**: U-02 で確定済み。キャッシュには大円距離のみを保存（U02-H4）。無効化は小学校区マスタ更新時のみ（Q7=A の Functional Design）。

---

### NFR-U03-R01: fail closed の CSV インポート（信頼性）

**要件**: 1 行でもエラーがあれば、DB の状態はインポート前と完全に同一。

**達成手段**: BR-DM01（原子性）。解析・検証フェーズでは DB を触らず、保存フェーズのエラーはロールバック。全エラーを行番号付きで一括報告（BR-DM02、Q4=A）。

---

### NFR-U03-R02: DB 復元時の再検証（信頼性、SECURITY-15）

**要件**: DB から読んだデータが不正な場合、その場で検出する。

**達成手段**: SQLAlchemy Core + 手書きマッパ（Q1=A）。行からドメイン型を再構築する際、`__post_init__` が再実行される。DB に不正データ（緯度 95.0 等）が混入していれば例外を送出する。**DB の破損が下流へ伝播しない。**

---

### NFR-U03-S01: 個人情報の保存（セキュリティ、SECURITY-01）

**要件**: 職員の氏名・居住小学校区（個人情報）を保存時に暗号化する。

**達成手段**: データディレクトリを暗号化ボリューム上に配置（shared-infrastructure.md、SECURITY-01）。**U-03 が個人情報を保存する最初のユニットである。**

---

### NFR-U03-S02: ログとエラーに個人情報を含めない（セキュリティ、SECURITY-03）

**要件**: CSV インポートのエラー報告・ログ・例外に、職員の氏名・居住小学校区を含めない。

**達成手段**: BR-DM14。職員 ID と行番号のみを含める。

---

### NFR-U03-S03: パラメータ化クエリ（セキュリティ、SECURITY-05）

**要件**: SQL は必ずパラメータ化クエリを使う。文字列連結でクエリを組み立てない。

**達成手段**: SQLAlchemy Core は、値をバインドパラメータとして扱う。生の SQL 文字列に値を連結しない。**SQL インジェクション（MU-02 の親戚）を構造的に防ぐ。**

---

### NFR-U03-M01: SQLite → PostgreSQL 移行（保守性、U01-H18）

**要件**: SQLite から PostgreSQL への移行を、接続文字列の変更とマイグレーション再適用で済ませる。

**達成手段**:
- SQLAlchemy Core（生の SQL を書かない、方言差を吸収）
- Alembic（マイグレーション）
- 相関サブクエリ（ウィンドウ関数の方言差を避ける、Q3=A）
- SQLite 固有の SQL を書かない

---

## 3. テスト戦略（Q5=A）

| 項目 | 決定 |
|------|------|
| テスト DB | **インメモリ SQLite（`:memory:`）、テストごとに新規** |
| 構築 | マイグレーションを適用する |
| PRAGMA | テスト DB にも適用する（特に `foreign_keys=ON`） |
| モック | **使わない**。SQL の正しさ（制約・CASCADE・クエリ）を実 DB で検証する |

**モックを使わない根拠**: P-DM01〜P-DM05 は SQL の正しさそのものを検証する。モックでは制約も CASCADE も検証できない。
