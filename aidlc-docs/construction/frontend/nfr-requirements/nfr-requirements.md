# U-08 frontend — 非機能要件（NFR Requirements）

**ユニット**: U-08 frontend
**技術スタック**: React 18 + TypeScript(strict) + Vite / fast-check / Vitest + Testing Library（+ Playwright 任意）。詳細は `tech-stack-decisions.md`。

各要件に `NFR-FE-*` の識別子を付す。

---

## 1. 性能（Performance）

| ID | 要件 | 目標 | 根拠 |
|----|------|------|------|
| NFR-FE-P1 | 初期表示 | 庁内 LAN で主要画面が実用的に即時表示（目安 2 秒以内の初期描画） | 業務ツール、小規模アセット |
| NFR-FE-P2 | 最適化ジョブのポーリング | 約 2 秒間隔（機能設計 Q4=A）。非終端の間のみ実行し、終端で停止 | サーバー負荷の抑制、多重投入防止（FE-35） |
| NFR-FE-P3 | 一覧描画 | 割当一覧（想定 数百件規模）を体感遅延なく描画 | PoC 規模（施設×職員） |
| NFR-FE-P4 | バンドルサイズ | 過大な UI キットを避け、必要最小限に保つ | エバーグリーン前提、庁内配信 |

## 2. スケーラビリティ（Scalability）

| ID | 要件 | 内容 |
|----|------|------|
| NFR-FE-S1 | 同時利用 | 小規模（割当担当者 P-01/管理者 P-02、数名規模）。水平スケール不要 |
| NFR-FE-S2 | データ規模 | マスタ・割当は PoC 規模。クライアント側での大規模データ処理は行わない（重い計算はバックエンド） |

## 3. 可用性・信頼性（Availability / Reliability）

| ID | 要件 | 内容 |
|----|------|------|
| NFR-FE-A1 | バックエンド不達時 | ネットワーク／5xx を汎用エラーとして表示し、再試行導線を提供（機能設計 §5） |
| NFR-FE-A2 | セッション失効 | 任意リクエストの `401` で V-01 へ遷移し、操作の取りこぼしを防ぐ（FE-50） |
| NFR-FE-A3 | ジョブ画面離脱 | ポーリングを画面ライフサイクルに紐づけ、再訪時は `job_id` で状態を再取得 |
| NFR-FE-A4 | 冪等でない操作 | 実行中はボタンを無効化し二重送信を防ぐ（FE-35） |

## 4. セキュリティ（Security）

**境界**: 認証・認可・IP 制限・レート制限・セキュリティヘッダはすべて **U-07（バックエンド）** が担う。フロント固有の要件は以下に限定。

| ID | 要件 | 内容 | 根拠 |
|----|------|------|------|
| NFR-FE-SEC1 | トークン非保持 | セッションは HttpOnly Cookie。JS でトークンを保持・保存しない | BR-API21 / FE-52 |
| NFR-FE-SEC2 | XSS 防止 | ユーザ／サーバ由来文字列を危険な innerHTML 等で描画しない。React の既定エスケープに依拠し、`dangerouslySetInnerHTML` を使わない | SECURITY-04/09 の趣旨 |
| NFR-FE-SEC3 | エラー非開示 | バックエンドのエラーメッセージをそのまま表示（内部情報は元々含まれない）。フロントで内部状態を露出しない | SECURITY-09 / FE-53 |
| NFR-FE-SEC4 | 通信 | HTTPS 前提（TLS 終端は公開基盤、Secure Cookie）。ベース URL は外部化設定 | 共有インフラ |

## 5. ユーザビリティ・アクセシビリティ（Usability / Accessibility）

| ID | 要件 | 内容 |
|----|------|------|
| NFR-FE-U1 | 言語 | UI は日本語。エラー・ラベルも日本語 |
| NFR-FE-U2 | アクセシビリティ | **WCAG 2.1 AA を目標**（JIS X 8341-3 整合）。セマンティック HTML、キーボード操作、フォームラベル、十分なコントラスト。PoC では実務的範囲で適用 |
| NFR-FE-U3 | フィードバック | ローディング・空状態・成功/失敗を明示（LoadingIndicator / EmptyState / ErrorBanner） |
| NFR-FE-U4 | フォーム | 軽量なクライアント検証（FE-30 系）で即時フィードバック。真実の源はバックエンド |

## 6. 保守性（Maintainability）

| ID | 要件 | 内容 |
|----|------|------|
| NFR-FE-M1 | 型付け | TypeScript strict。DTO を型として写し、乖離を写像 PBT で検知 |
| NFR-FE-M2 | 品質ゲート | `tsc --noEmit`、ESLint、Vitest、fast-check（`tech-stack-decisions.md` §4） |
| NFR-FE-M3 | 境界（H-5） | `src/frontend/` はバックエンドユニットを import しない。リンタ／ビルド規則で機械検証（バックエンド R-8 と対） |
| NFR-FE-M4 | 設定外部化 | バックエンド URL は `config/`（NFR-M03/M05） |

## 7. 対応環境

| ID | 要件 | 内容 |
|----|------|------|
| NFR-FE-E1 | ブラウザ | モダンなエバーグリーンのみ（最新 Chrome/Edge/Firefox）。レガシー非対応 |
| NFR-FE-E2 | 端末 | 庁内イントラネット PC のデスクトップ。モバイル最適化は対象外 |

---

## 8. テスト戦略（PBT 拡張ブロッキングへの適合）

- **PBT（fast-check）**: 
  - DTO ↔ ビューモデルの写像がラウンドトリップで情報を失わない（バックエンド U-07 の P-API01 に対応するフロント版）。
  - フォーム検証規則（FE-30〜34）のプロパティ（例: 全重み 0 は常に無効、負値は常に無効）。
- **コンポーネントテスト（Vitest + Testing Library）**: API をモックし、各 Container の状態遷移・エラー表示（401→ログイン、400→違反表示、CSV 行エラー表示）を検証。
- **E2E（Playwright、任意）**: 価値実証フローの通し（ログイン→イベント→マスタ→申告→充足→最適化→割当）。
- **境界検査（H-5）**: フロント→バックエンド import 禁止の機械検証。
