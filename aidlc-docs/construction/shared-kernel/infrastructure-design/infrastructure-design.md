**U-01 `shared-kernel` はインフラ表出を一切持たない。マッピングすべきインフラサービスが存在しない。**

## 4. U-01 がインフラを持たないことの設計上の意味

これは欠落ではなく、**U-01 の位置づけそのものである**。

### 4.1 依存グラフの根としての制約

`unit-of-work-dependency.md` により、U-01 は依存グラフの根であり、何にも依存しない。**インフラコンポーネントを持つということは、そのコンポーネントのライブラリに依存するということである。** それは U-01 の位置づけと矛盾する。

### 4.2 6 ユニットが安全に共有できる理由

U-01 のプロダクションコードは**標準ライブラリのみに依存する**（`nfr-design/logical-components.md`）。

したがって:

- SQLite を PostgreSQL に替えても、U-01 は変わらない
- Redis を導入しても、U-01 は変わらない
- Web フレームワークを FastAPI から替えても、U-01 は変わらない（Pydantic を U-07 に閉じ込めたため）

**インフラの選択が U-01 を経由して他ユニットへ伝播しない。** これが 6 ユニットが U-01 を安全に共有できる理由である。

### 4.3 例外の送出とログの分離

U-01 は例外を**送出する**が、ログには**書かない**。

| 責務 | 所有 |
|------|------|
| 生成時バリデーションの失敗を検出し、`DomainError` を送出する | **U-01** |
| `DomainError` を捕捉し、構造化ログへ文脈属性を記録する | U-07（グローバルエラーハンドラ、申し送り U01-H25） |
| 利用者へ汎用エラーメッセージを返す | U-07 |
| 監査ログへ記録する | U-06 |

**この分離により、U-01 はログライブラリにもログ基盤にも依存しない。** モニタリングインフラが N/A である理由である。
